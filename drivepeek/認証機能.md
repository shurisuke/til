# DrivePeek認証機能

## 概要
DrivePeekはDeviseをベースとした認証システムを採用。
メール/パスワード認証とSNS認証（X, LINE）の両方に対応している。

## 技術スタック
- **Devise**: Rails標準の認証ライブラリ
- **OmniAuth**: SNS認証（Twitter2, LINE）
- **Identityモデル**: SNS連携情報を管理

## Deviseモジュール構成

```ruby
devise :database_authenticatable, :registerable,
       :recoverable, :rememberable, :validatable,
       :confirmable,
       :omniauthable, omniauth_providers: [:twitter2, :line]
```

| モジュール | 機能 |
|-----------|------|
| database_authenticatable | メール/パスワード認証 |
| registerable | ユーザー登録 |
| recoverable | パスワードリセット |
| rememberable | ログイン状態の保持（2週間） |
| validatable | メール/パスワードのバリデーション |
| confirmable | メールアドレス確認 |
| omniauthable | SNS認証（X, LINE） |

## SNS認証の設計

### Identityモデル
SNS連携情報を別テーブルで管理（1ユーザーが複数SNSと連携可能）

```ruby
class Identity < ApplicationRecord
  belongs_to :user
  validates :provider, presence: true
  validates :uid, presence: true, uniqueness: { scope: :provider }
end
```

### SNS認証フロー

1. **新規ユーザー**: SNS認証 → User作成（メール不要）→ プロフィール設定へ
2. **既存ユーザー**: SNS認証 → Identity検索 → ログイン
3. **SNS連携追加**: ログイン済み → SNS認証 → Identity追加

### SNSのみユーザーの特別処理

```ruby
# SNS認証のみのユーザーはパスワード不要
def password_required?
  super && !sns_only_user?
end

# SNS認証のみのユーザーはメール不要
def email_required?
  !sns_only_user?
end

def sns_only_user?
  (registering_via_sns || identities.exists?) && email.blank?
end
```

## メール確認（Confirmable）の設計

### 設計方針
- **初回登録時**: メール確認不要（SNSログインとの整合性）
- **メールアドレス変更時**: 再確認メールを送信（reconfirmable）

### 設定値

| 設定 | 値 | 説明 |
|-----|---|------|
| allow_unconfirmed_access_for | nil | 確認なしでもアクセス可能 |
| confirm_within | 30分 | 確認トークンの有効期限 |
| reconfirmable | true | メール変更時に再確認 |

### メールアドレス変更フロー

1. ユーザーが新しいメールアドレスを入力
2. `unconfirmed_email`に保存、確認メール送信
3. 確認リンクをクリック → `email`に反映

```ruby
# Devise 5.0 + Rails 8 対応の手動実装
def email=(value)
  new_email = value.to_s.strip.downcase
  current_email = read_attribute(:email)&.downcase

  if self.class.reconfirmable && persisted? && new_email != current_email && new_email.present?
    self.unconfirmed_email = value.to_s.strip
    @reconfirmation_required = true
  else
    super
  end
end
```

## OmniAuthコールバック処理

```ruby
def handle_oauth(provider_name)
  auth = request.env["omniauth.auth"]

  # ログイン済みユーザーからのSNS連携
  if user_signed_in?
    current_user.link_omniauth(auth)
    redirect_to sns_settings_path, notice: "#{provider_name}と連携しました"
    return
  end

  # SNS連携済みユーザーを検索
  @user = User.from_omniauth(auth)

  if @user
    # 既存ユーザー：通常ログイン
    sign_in @user, event: :authentication
    redirect_to session.delete(:redirect_after_auth) || new_plan_path
  else
    # 新規ユーザー：直接登録
    @user = User.create_from_omniauth(auth)
    sign_in @user, event: :authentication
    redirect_to profile_settings_path(from: "signup")
  end
end
```

## 設計のポイント

1. **SNSユーザーとメールユーザーの統一**: 同じUserモデルで管理、メール/パスワードはオプショナル
2. **複数SNS連携**: Identityテーブルで1:Nの関係を実現
3. **初回確認スキップ**: SNSログインとの整合性のため、初回登録時のメール確認は不要
4. **reconfirmable**: メールアドレス変更時のセキュリティ確保
